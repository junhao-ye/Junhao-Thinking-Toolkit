# 解決複雜問題

用專家會診看互補立場，用第一性原理重建受慣例束縛的方案，用跨領域借解找本領域之外的機制。只需檢查前提或已明確要求互動解題時，直接跳到對應的輕量入口。

## 專家會診

1. 依問題挑選 3 個互補的專業視角，說明各自為何必要。
2. 不模仿真實人物，也不把角色名稱當證據。
3. 每個視角獨立回答：
   - 如何重新定義問題；
   - 最推薦的解題路徑；
   - 其他視角容易漏掉的風險；
   - 哪項新證據會讓它改變判斷。
4. 讓三個視角交叉質疑，分出共同事實、真實分歧與分歧背後的假設。
5. 綜合輸出：推薦方案、適用條件、最大風險、退出條件、第一步。

選角原則：至少一個視角負責可行性或執行、一個負責目標或使用者價值、一個負責風險或反證。依問題調整，不要固定套用職稱。

只想比較不同立場時用簡版。依使用者指定的數量列出彼此有實質差異的觀點，未指定時取 3 個。納入一個能合理質疑當前看法的立場，逐一交付它重視的結果、看見的機會與代價，以及會改變判斷的證據。最後指出最重要的一項分歧。

## 第一性原理

1. 把問題拆成：
   - 已確認、無法繞過的基本事實；
   - 被慣性接受但未驗證的假設；
   - 真正目標；
   - 資源、時間、制度與風險限制。
2. 暫時移除行業慣例與既有方案，從基本事實重新推導選項。
3. 將新方案與原方案比較，指出哪些舊動作只是在修補表面。
4. 為新路徑列出必要前提與第一個驗證動作。

不要把仍可爭論的偏好誤稱為基本事實，也不要假裝物理、法律、倫理或安全限制不存在。

## 跨領域借解

1. 移除行業術語，把困境抽象為可跨領域比較的結構。
2. 找出核心矛盾與普通解法失效原因。
3. 從歷史與至少 3 個彼此距離較遠的領域尋找相似機制。
4. 每個候選案例說明原問題、解法機制、結構相似處、可遷移部分與失效條件。
5. 依「結構相似度、可執行性、風險、可逆性」排序，選出最多 3 個機制。
6. 把機制翻譯回當前情境，設計一個低成本、可逆的試驗。

不要只因故事有趣就判定可遷移。表面類比若沒有相同因果機制，應淘汰。

## 假設檢驗

1. 從使用者的想法或方案找出一到三個左右結論的假設，標記哪些是原文明說、哪些是推得。
2. 逐項列出支持線索、最有力的反例或替代解釋，以及什麼觀察能區分兩者。缺乏線索時標為待驗證。
3. 交付「假設 → 依據與反證 → 判斷改變的條件」。有下一步需求時，挑出最值得優先驗證的一項。

## 逐步引導

1. 依題目和使用者熟悉度，把目標拆成有先後順序、可檢查的小步驟。先交付當前一步、完成標準與一個能推進的問題。
2. 收到回覆後，指出哪裡已成立、哪裡需要修正，給下一步。若使用者卡住，先提供一個具體提示。若改要完整流程，直接列出全部必要步驟與檢查點。
3. 目標達成、使用者要求停止，或缺少關鍵資料無法推進時收束。交付已確認結果和仍待完成的部分。

## 共通驗證

- 方案必須連到使用者目標與限制。
- 每個關鍵建議至少附一個失效條件。
- 若有不可逆、高成本或高風險行動，先改成小規模、可回退的測試。
