# 學習與核查

根據需求選擇一種方法。只有使用者同時需要「理解」與「驗證」時，才串接兩種方法。

## 雙層解釋

適用：完全陌生、只靠類比容易產生假懂。

1. `直覺層`：用日常語言把機制拆成有先後關係的小步驟，走完一個具體例子。若類比能幫助理解，指出它對應到哪個步驟，以及哪裡會失準。
2. `專業層`：用準確術語說明機制、邊界、前提與常見誤解。
3. 建立直覺說法與專業術語的對照表。
4. 指出最容易理解錯的 1–3 點。
5. 提出 3 個理解檢查題，至少一題要求遷移到新情境。

不要把直覺層寫成兒童化語氣，也不要用不準確類比取代真實機制。

## 反向拆解

適用：使用者提供產品頁、文章、網站、方案、流程、看板或其他成品，想知道為何有效。

1. 用一句話定義成品解決的問題。
2. 分析服務對象、目標、結構或流程、關鍵品質選擇、完成標準。
3. 區分可遷移規律與案例專屬細節。
4. 輸出：
   - 3–5 條可複用規律；
   - 一份可照做的操作清單；
   - 一個最小練習。

若無法讀取成品或缺少關鍵部分，先說明可見範圍，不要補寫不存在的設計意圖。

## 橫縱分析

適用：需要建立對陌生領域的可追溯全景。

### 縱向

- 誕生背景、需求與關鍵推動者。
- 重要轉折、成功、失敗與因果鏈。
- 早期選擇如何形成今日的能力、路徑依賴與包袱。

### 橫向

- 選擇真正可比的對象並說明理由。
- 使用同一組維度比較強項、短板與差異。
- 解釋使用者或市場為何選擇、放棄或切換。

### 合併判斷

- 歷史能力與約束如何影響未來。
- 提出最多 3 條未來路徑。
- 為每條路徑列出成立條件、領先指標與失效訊號。

預設輸出：`核心結論 → 時間線 → 橫向對照 → 詳細分析 → 未來路徑 → 待確認事項`。除非使用者指定長篇報告，先交付緊湊版本，再視需要擴寫。

## 事實核查

適用：核查一句說法、一組數據、一段論證或方案依據。

1. 拆成外部可驗證事實、從事實推出的結論、價值判斷。
2. 對事實逐項檢查來源、樣本、日期、定義與完整上下文。
3. 標記為：`已證實`、`大致成立但需收窄`、`有爭議`、`證據不足`、`錯誤`。
4. 檢查推理是否：
   - 偷藏未驗證假設；
   - 把相關當因果；
   - 忽略基準率、替代解釋或反例；
   - 超出樣本、時間或地域範圍。
5. 輸出可信部分、需要修正處、最大推理缺口、補強後版本與信心水準。

## 證據規則

- 對時效性主張查到執行當日；優先官方資料、原始數據、論文、財報、法規與第一手訪談。
- 重要主張就近附來源與日期；來源衝突時並列，不替任一方消除矛盾。
- 找不到證據時寫「尚未核實」，不要以流行度代替真實性。
