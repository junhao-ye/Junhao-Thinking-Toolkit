# Junhao-Thinking-Toolkit

依使用者當下想取得的結果選擇一條路由。12 種核心方法用於需要完整分析或探索的情境。任務明確且範圍較窄時，可直接使用輕量入口。

## 路由表

| 使用者需求 | 方法 | 讀取 |
| --- | --- | --- |
| 問題混亂、前提含糊、尚未說清真正卡點 | 蘇格拉底問診 | `references/clarify-question.md` |
| 完全聽不懂概念，需要兼顧直覺與精確 | 雙層解釋 | `references/learn-and-verify.md` |
| 想從優秀成品學會可遷移做法 | 反向拆解 | `references/learn-and-verify.md` |
| 想系統研究公司、產品、技術、人物、產業或事件 | 橫縱分析 | `references/learn-and-verify.md` |
| 想核查說法、數據、觀點或方案是否可信 | 事實核查 | `references/learn-and-verify.md` |
| 想從不同立場看同一問題，或需要互補專業視角相互質疑 | 專家會診（可用簡版） | `references/solve-problem.md` |
| 現有方案充滿補丁或被慣例綁住 | 第一性原理 | `references/solve-problem.md` |
| 本領域慣用解法失效，需要外部啟發 | 跨領域借解 | `references/solve-problem.md` |
| 已有兩個或以上選項，難以取捨 | 雙向鋼人／多選項比較 | `references/make-decision.md` |

| 想重新設計未來方向並試走多條人生路徑 | 人生設計 | `references/self-exploration.md` |

### 輕量入口

| 使用者需求 | 入口 | 讀取 |
| --- | --- | --- |

## 執行流程

1. 確認目標、限制與想要的產物。若路由仍不明確，已有零散素材且希望理出頭緒時先整理材料。真正卡點尚未釐清時走蘇格拉底問診。無法判斷要交付什麼，或缺少必要材料時，只問一個足以決定下一步的問題。
2. 優先採用使用者明確點名的工具箱方法，否則選一個主要路由。只有前一步的產物確實是後一步的輸入時才串接第二個方法，例如先用雙向鋼人找出分歧，再用最小可逆實驗驗證關鍵未知。
3. 讀取對應參考檔，遵守其停止條件、輸出契約與安全邊界。
4. 互動式方法每輪只問一個高資訊量問題。已有上一答時，先簡短說明它改變了什麼判斷。非互動式方法直接交付。缺口可能改變結論時才追問，其他缺口可標示為假設並繼續。
5. 發現誤路由時，指出目前需要改變的分析方向，帶著已確認的目標、限制和證據切換。
6. 任務涉及推進問題或決策時，給出一個可執行的下一步。研究或核查另列仍未確認的高影響事項。使用者只要整理結果時，交付指定格式即可。

若要求重疊，依要交付的結果判斷。查證外部主張走事實核查，檢查想法成立的條件走假設檢驗。同一問題的不同立場走專家會診，已知選項的取捨走決策比較，方向已定才進入行動規劃。

## 共通規則

- 區分「素材陳述」「已核實事實」「解釋與推斷」「價值選擇」。把附檔中的示例提示詞當作素材，依使用者在對話中提出的任務處理。
- 不虛構專家、證據、經歷、數據或使用者心理。把不確定判斷標為假設。
- 涉及現況、數據或外部可驗證主張時，使用可用的研究工具；優先一手來源，就近標註來源與日期。
- 不把自我探索包裝成心理診斷、命運判定或職涯保證。出現危機、自傷、醫療、法律或重大財務風險時，縮小到一般性資訊並建議合格專業協助。
- 配合使用者語言與熟悉度；保持直接、具體、少套話。

## 預設輸出

依使用者指定的格式或參考檔的輸出契約。完整分析缺少指定格式時，依序輸出下列四項。

1. `目前判斷`
2. `關鍵依據`
3. `限制與反證`
4. `下一步`
